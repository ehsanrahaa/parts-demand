# تقاضای قطعات یدکی خودروهای سواری و وانت — تحقیق تاریخی یک‌ساله

این پروژه از کانال‌های عمومی تلگرام (فروشندگان و پخش‌کنندگان قطعات، به‌همراه چند کانال خبری) پست‌های یک سال گذشته را می‌خواند، نام قطعه و خودرو را در متن پیدا می‌کند و جدول‌های فراوانی می‌سازد. خروجی برای راه‌اندازی یک سایت فروش قطعات است: کدام قطعه، برای کدام خودرو، چند بار و با چه میزان بازدید عرضه/تقاضا شده است.

پروژه کاملاً از `danesh-agent` جدا است: نه فایلی از آن را تغییر می‌دهد، نه وابستگی مشترکی دارد. فقط الگوی «دریافت با محدودیت نرخ، صفحه‌بندی، ذخیره‌ی وضعیت و ارسال به تلگرام» از آن گرفته شده است.

## خروجی‌ها

همه در `out/` ساخته می‌شوند:

| فایل | محتوا |
|------|-------|
| `parts_frequency.csv` | همه‌ی ۱۹۷۵ ترکیب قطعه×خودرو (۷۹ قطعه × ۲۵ خودرو) با شمارش‌ها؛ مرتب بر اساس تقاضا، ردیف‌های صفر ته فایل |
| `top500.csv` | ۵۰۰ ترکیب اول همان جدول |
| `parts_by_mentions.csv` | ۷۹ قطعه به‌صورت تجمیعی (بدون تفکیک خودرو) با برندهای دیده‌شده |
| `vehicles.csv` | ۲۵ خودرو و تعداد قطعه‌های دیده‌شده برای هرکدام |
| `summary.json` | آمار پوشش: تعداد پست، بازه، ترکیب‌های دیده‌شده، برندها |
| `report.html` | همان گزارش با چیدمان راست‌به‌چپ |
| `report.pdf` | **گزارش اصلی**؛ همهٔ جدول‌ها با برندهای دیده‌شده و برندهای پیشنهادی بازار |
| `report.md` | نسخهٔ متنی گزارش برای گیت و بازبینی سریع |

PDF با Chrome/Chromium بی‌سر ساخته می‌شود (روی مک: Chrome نصب باشد؛ روی GitHub Actions از Chrome آمادهٔ runner استفاده می‌شود). اگر Chrome پیدا نشود، بقیهٔ خروجی‌ها ساخته می‌شوند و فقط PDF با هشدار رد می‌شود.

ستون‌های عددی CSV با ارقام لاتین و فایل با UTF-8 BOM ذخیره می‌شود تا اکسل فارسی درست باز کند. ستون‌های مهم:

- **پست فروشندگان**: تعداد پست‌های متمایز کانال‌های فروشنده که این قطعه (و برای ترکیب‌ها، این خودرو) در آن‌ها آمده است.
- **همان در ۹۰ روز**: همان شمارش در ۹۰ روز آخر — برای دیدن روند تازه.
- **پست خبری**: فقط از کانال‌های خبری؛ در رتبه‌بندی تقاضا حساب نمی‌شود و صرفاً برای مقایسه است.
- **مجموع بازدید**: مجموع بازدید پست‌های فروشنده (از پیش‌نمایش عمومی تلگرام). سیگنال محبوبیت است، نه تعداد خرید.
- **برندهای دیده‌شده**: برندهایی که در همان پست‌ها کنار قطعه ذکر شده‌اند (مشاهده).
- **برندهای پیشنهادی بازار**: برندهای آمادهٔ هر دسته از `catalog_seed.json` (تعمیم دسته، نه مشاهده).
- گزارش PDF/HTML برای هر قطعه و هر ترکیب هر دو ستون برند را دارد؛ جدول جداگانهٔ برندها هم پست، قطعه، بازدید و «در فهرست آماده» را نشان می‌دهد.

## روش

1. `channels.txt`: کانال‌های فروشنده؛ `news.txt`: کانال‌های خبری. هر خط یک نام بدون `@`.
2. برداشت از پیش‌نمایش عمومی `https://t.me/s/<channel>` با صفحه‌بندی `?before=<min id>` تا رسیدن به بازه‌ی زمانی. فاصله‌ی ۰٫۹ ثانیه بین درخواست‌ها با ۳ کارگر موازی؛ تلگرام به درخواست‌های پشت‌سرهم سریع از یک IP خطای اتصال می‌دهد.
3. تطبیق نام قطعه/خودرو/برند در متن نرمال‌شده (ی/ک عربی، نیم‌فاصله، ارقام فارسی) با مرزهای واژه‌ی فارسی‌آگاه. یک پست اگر فقط یک خودرو را نام برده باشد به همان خودرو نسبت داده می‌شود؛ اگر چند خودرو را نام برده باشد، برای همه‌ی جفت‌های قطعه×خودرو ثبت می‌شود.
4. همه‌ی پست‌ها در `data/parts.db` (SQLite) می‌مانند؛ `rebuild` بدون شبکه دوباره استخراج می‌کند. بنابراین تغییر فهرست قطعات/نام‌های جایگزین نیازی به برداشت دوباره ندارد.

## وضعیت اندازه‌گیری‌شده (۲۰۲۶-۱۱-۱۷)

آخرین اجرای کامل یک‌ساله:

```json
{"posts":1188,"posts_seller":1083,"posts_news":105,"channels":28,
 "first":"2025-11-17","last":"2026-11-17","posts_scanned":9982,
 "combos_total":1975,"combos_with_hits":441,"parts_total":79,"parts_with_hits":68,
 "mentions_seller":1511,"views_seller":945327}
```

- ۲۸ کانال فروشنده + ۳ کانال خبری، ۹۹۸۲ پست خوانده شد، ۱۰۸۳ پست فروشنده نام قطعه داشت.
- ۴۴۱ ترکیب از ۱۹۷۵ ترکیب دست‌کم یک اشاره دارند؛ ۶۸ قطعه از ۷۹ قطعه دیده شده‌اند.
- ۵ قطعهٔ اول: کیت کلاچ، شمع، رادیاتور آب، دینام، استارت.
- ۵ ترکیب اول: کیت کلاچ×پراید، کیت کلاچ×پژو ۴۰۵، سوپاپ×پژو ۴۰۵، رادیاتور آب×پراید، سوپاپ×پراید.
- اجرای کامل حدود ۴٫۵ دقیقه طول می‌کشد (۳۲ کانال، ۳ کارگر).

**صداقت دربارهٔ پوشش:** ۵۹ ردیف آخر `top500.csv` صفر هستند (ترکیب‌هایی که در یک سال دیده نشدند). این ردیف‌ها برای کامل بودن ماتریس ۷۹×۲۵ مانده‌اند، نه به‌عنوان تقاضا. عددهای واقعی همان ۴۴۱ ردیف اول هستند.

## محدودیت‌ها

- **نرخ کلیک گوگل قابل استخراج نیست.** Google Trends و Google Keyword Planner API عمومی و بدون حساب ابری ندارند و اسکرپ گوگل مسدود می‌شود. بنابراین «کلیک گوگل» در این پروژه با دو سیگنال جایگزین شده است: میزان عرضه/تکرار در پست فروشندگان و مجموع بازدید همان پست‌ها. این‌ها تقاضای مشاهده‌شده را نشان می‌دهند، نه جست‌وجوی گوگل را.
- **بازدید فقط برای کانال‌های عمومی تلگرام در دسترس است** و از پیش‌نمایش عمومی خوانده می‌شود؛ اگر کانالی بازدید خود را پنهان کند، صفر ثبت می‌شود.
- نمونه‌گیری از عرضه است نه خرید: پستی که فروشنده می‌گذارد نشانه‌ی تقاضاست، ولی شمار واقعی فروش را نمی‌بینیم.
- فهرست قطعات ثابت و دستی است (۷۹ قطعه، ۲۵ خودرو). قطعه‌ی خارج از فهرست شمرده نمی‌شود. برای گسترش، `catalog_seed.json` را ویرایش و `build_catalog.py` را اجرا کنید.
- داده‌ی یک سال به عقب به سیاست نگهداری تلگرام و عمومی‌بودن کانال وابسته است؛ کانال حذف‌شده یا خصوصی‌شده از دست می‌رود.

## اجرا

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # اختیاری: TELEGRAM_TOKEN و CHAT_ID برای ارسال خلاصه
```

`collector.py` خودش فایل `.env` کنار خودش را می‌خواند (بدون وابستگی اضافه) و فقط کلیدهای تعریف‌نشده در محیط را پر می‌کند؛ در GitHub Actions همان secrets مستقیم به محیط می‌آیند و نیازی به فایل نیست.

```bash
python collector.py collect --days 365 --pages 40 --workers 3   # برداشت
python collector.py report --top 500                            # ساخت جدول‌ها
python collector.py digest                                      # ارسال خلاصه + PDF + CSV به تلگرام (اگر توکن باشد)
python collector.py rebuild                                     # استخراج دوباره از پست‌های ذخیره‌شده، بدون شبکه
python collector.py selftest                                    # تست تطبیق نام‌ها
python collector.py probe --days 365                            # سلامت و حجم هر کانال
```

- `collect` افزایشی است: پست‌های دیده‌شده دوباره شمرده نمی‌شوند. برای اجرای روزانه `--days 30 --pages 10` کافی است؛ ماهی یک‌بار `--days 365 --pages 40` دوباره همه‌چیز را می‌بیند.
- `--channels a b c` فهرست کانال‌های فروشنده را موقتاً جایگزین می‌کند. `--no-news` کانال‌های خبری را نادیده می‌گیرد.
- `--max-runtime` سقف ثانیه‌ی برداشت است (پیش‌فرض ۲۴۰۰).

## افزودن قطعه، خودرو یا کانال

- قطعه/خودرو: `catalog_seed.json` را ویرایش کنید (`key`, `name`, `cat`/`models`, `aliases`) و `python build_catalog.py` بزنید؛ سپس `rebuild` و `report`. نام‌های جایگزین کوتاه و پرکاربرد (مثل «لنت» یا «۴۰۵») را هم اضافه کنید، وگرنه پست‌های زیادی از دست می‌رود.
- کانال: نام را به `channels.txt` (فروشنده) یا `news.txt` (خبری) اضافه کنید و `python collector.py probe` بزنید تا مطمئن شوید صفحه‌ی عمومی باز می‌شود و پست دارد.

## اجرای خودکار روی GitHub Actions

`.github/workflows/collect.yml` روزانه یک برداشت افزایشی و روز اول هر ماه یک اجرای کامل می‌زند، گزارش را به‌عنوان artifact نگه می‌دارد و `data/parts.db` را روی شاخه‌ی `state` ذخیره می‌کند تا تاریخ بین اجراها بماند. با `workflow_dispatch` هم می‌توان دستی اجرا کرد.

برای فعال‌شدن ارسال گزارش به تلگرام، در Settings → Secrets and variables → Actions دو secret بسازید: `TELEGRAM_TOKEN` و `CHAT_ID`. هر دور، خلاصه + `report.pdf` + دو CSV را می‌فرستد؛ بدون این‌ها همه‌چیز کار می‌کند و فقط خلاصه در لاگ می‌آید. هیچ توکنی در کد نیست.

اجرای کامل اول (بازگشت یک‌ساله) را یک‌بار دستی با `days=365` بزنید؛ بعد از آن اجرای روزانه کافی است.
